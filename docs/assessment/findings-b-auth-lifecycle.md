## Verdict

## Findings

**Critical:**

- ~~**Open redirect in `/auth/callback` `?next=` validation.**~~ **RESOLVED** — the check now verifies the parsed URL's origin (`safeNextPath`, `utils/auth.ts`), closing both the backslash and the tab/newline variants. Original finding: `route.ts:21` accepts any value starting with `/` that isn't `//`. A value like `?next=/\evil.com` (or URL-encoded `/%5C%5Cevil.com`, which `searchParams.get` decodes) passes the check, but WHATWG URL parsing treats `\` as a path separator for `http(s)` URLs, so `new URL('/\\evil.com', request.url)` at `route.ts:33` resolves to `https://evil.com/` and `NextResponse.redirect` sends the victim off-site. Same bypass via tab-stripping (`/%09/evil.com` → `//evil.com` → host `evil.com`). Fix: require `next` to match `/^\/(?!\/|\\)[^\\]*$/` or compare `new URL(next, request.url).origin === new URL(request.url).origin` before redirecting. Note the redirect happens unconditionally (`:30-33` — intentionally, even on failed exchange), so no valid session/token is needed for the redirect to fire.

**Required:**

- ~~**Admin "Add account" confirmation link skips `/auth/callback`.**~~ **RESOLVED** — `admin/users/page.tsx` now uses `confirmEmailRedirect()`, so admin-created accounts go through `/auth/callback` to `/auth/login?confirmed=1` exactly like self-registered ones.
- ~~**`profiles.updated_at` is relied on but not maintained by any migration.**~~ **RESOLVED** — `202610181700_profiles_updated_at.sql` adds the column (backfilled from `created_at`, NOT NULL, default `now()`) and a `profiles_touch` BEFORE UPDATE trigger on the shared `touch_updated_at()`. Verified live: an update advanced `updated_at`.

**Nit:**

- `proxy.ts:57-61` redirects unauthenticated visitors to `/auth/login` without preserving the attempted path; after login `login/page.tsx:45` always pushes `/dashboard`. Harmless, but deep links to e.g. `/teams/…` lose their destination.
- An admin can demote *themself* via the `/admin/users` role dropdown (`admin/users/page.tsx:181-190` guards only promotions; `protect_profile_role` only blocks non-admin changers and the last-admin demotion `202610170900:59-69`). Allowed by design, but a self-demotion removes the admin's own access mid-session — worth a confirm or `isMe` guard.
- `app/auth/callback/route.ts:17` casts `type` to `EmailOtpType` without whitelisting; invalid values just fail `verifyOtp` and still redirect — harmless but sloppy validation next to the redirect bug above.
- The consent gate is enforced only on `/dashboard` (`dashboard/page.tsx:124-127`). A non-consented logged-in user can deep-link straight to `/teams`, `/feedback`, etc. Matches CLAUDE.md's wording ("the dashboard sends users…") but is advisory rather than app-wide; consider moving the check into `proxy.ts` if the intent is a hard gate.

**FYI:**

- Session separation on admin add-account is correctly wired: `signup-client.ts` uses `createClient` from `@supabase/supabase-js` (not `@supabase/ssr`) with `persistSession: false`, so nothing touches the admin's cookie session (`signup-client.ts:10-23`, used at `admin/users/page.tsx:317`).
- `admin_delete_user` needs no explicit "last admin" check: callers must be admin (`202610161900:72`) and can't target themselves (`:76`), so ≥1 admin always remains. Self-delete is separately blocked for the last admin (`202610161300:131-135`).
- Sign-up role enforcement is defense-in-depth: even tampered `options.data.role` is coerced to `spectator` by `handle_new_user` (`202610170900:38`); staff/admin roles are then set via the admin's own `profiles.update` (`admin/users/page.tsx:334-344`), passing `protect_profile_role`'s admin check.
- Email enumeration is avoided on forgot-password (identical message regardless of account, `forgot-password/page.tsx:40-46`) and handled on admin add-account via `identities.length === 0` (`admin/users/page.tsx:329`). Register doesn't special-case it — an existing email shows "Check your email", which is the desired anti-enumeration behavior.
- `verifyOtp`/`exchangeCodeForSession` errors are deliberately swallowed in the callback (`route.ts:24-33`); the destination page explains failure (e.g. `reset-password/page.tsx:59-68`). Correct by design, just noting it pairs with the open-redirect finding.
- Staff can't read feedback since `202610162300:17-26` (policies replaced to admin-only) — consistent with CLAUDE.md.
- `handle_new_user` uses `on conflict (id) do nothing` (`202610170900:42`), so duplicate trigger fires are safe.
